# Shidea Hotspot Prediction

> 面向中文互联网的 Jev 驱动热点机会发现与人群分群引擎。

Shidea 不把热点系统做成“自动写内容”的工具，而是先解决更靠前的问题：**今天哪些信号值得追、为什么值得追、最适合谁关注。**

```text
国内热榜 / RSS / 新闻源
        ↓
采集、存储、去重
        ↓
事件聚类 + 动量计算
        ↓
Jev 多维并行判断
        ↓
分人群热点机会榜单
```

## Jev 是什么角色？

Jev 是本项目的高频判断引擎，而不是爬虫、搜索引擎或长文生成器。

| 层级 | 职责 |
| --- | --- |
| 采集与时间序列 | 收集国内平台热点，记录排名、出现次数和传播范围 |
| 代码 | 相似标题聚类；计算跨平台扩散、持续性、排名质量与排名变化形成动量 |
| Jev | 并行判断相关性、新颖度、可内容化程度、差异化空间、风险、事实核查需求、推荐角度与人群适配度 |
| Shidea 输出 | 将动量与 Jev 判断组合为机会分，并按不同用户群体分别排序 |

这使系统可以先用实时事实信号压缩候选集，再用 Jev 完成大量独立、小粒度判断，而不是把全部热榜都交给传统生成模型阅读。

## 当前功能

- 聚合中文热点、RSS 与新闻源，并将相似标题归并成事件。
- 基于跨平台扩散、出现次数、排名质量和排名变化计算可解释的事件动量。
- 使用 Jev 为候选事件打多维语义分，并输出机会分、风险和事实核查提示。
- 面向 7 类人群生成独立热点机会榜：

  - AI 开发者与技术构建者
  - 数码尝鲜与 AI 工具用户
  - 年轻趋势人群（18–28）
  - 职场成长人群（22–35）
  - 家庭决策人群（30–55）
  - 活力银发人群（55+）
  - 创业者与小微经营者

- 提供本地浅色结果看板，仅展示分群排序与分析结果；密钥只保留在本机 `.env`。
- 输出可读 Markdown 与可编程 JSON 报告。

## Jev 时延基准

在同一批 50 个热点、相同判断维度、每端 10 路并发、25 秒单请求上限的实测中，Jev 与传统大模型 JSON 分类 baseline 均为 0% 失败率：

| 指标 | Jev | 传统大模型 baseline |
| --- | ---: | ---: |
| 平均单条时延 | 1.18 秒 | 10.39 秒 |
| 中位数时延 | 1.18 秒 | 9.28 秒 |
| P95 时延 | 1.49 秒 | 20.50 秒 |
| 整批 50 条耗时 | 6.36 秒 | 55.31 秒 |
| 吞吐量 | 7.86 请求/秒 | 0.90 请求/秒 |

- Jev 的中位数延迟约快 **7.9 倍**。
- Jev 的 P95 延迟约快 **13.8 倍**，尾部稳定性更强。
- 整批处理速度约快 **8.7 倍**。

该实验只衡量时延与可用性，不将模型间的一致性误称为准确度。准确度比较需要独立人工标注的金标准。

## 快速开始

```bash
# 安装项目依赖
pip install -e .

# 配置 Jev 密钥；.env 不会被 Git 跟踪
cp .env.example .env
# 编辑 .env，填写 TYPESAFE_API_KEY

# 抓取热点
python -m trendradar

# 生成 Jev 机会报告
python -m trendradar.jev --top 10

# 打开本地结果看板
python -m trendradar.webapp
```

在浏览器打开 `http://127.0.0.1:8765`。报告写入 `output/jev-radar/<日期>/`：Markdown 适合阅读，JSON 适合接入后续工作流。

## 配置

`config/jev_radar.yaml` 用于定义创作者赛道、7 类人群、推荐内容角度、候选数量、机会分权重与 Jev 超时。动量始终由代码计算；未配置 Jev 密钥时，命令会降级为动量预筛，不会伪造语义分数。

## 边界

热点机会分不等于事实确认。对于健康、金融、公共政策、争议性事件或高风险内容，应先根据“事实核查需求”回到一手来源验证，再进行传播或创作。
